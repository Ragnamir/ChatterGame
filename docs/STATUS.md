# Статус этапов

Хронология прохождения этапов по протоколу `PLAN §1`. Запись добавляется по сдаче этапа,
удаляется только если этап отменён решением владельца.

Формат записи:

```
## <STAGE> — <название>
Дата: YYYY-MM-DD
Гейт: GREEN | RED | N/A
Сделано:
Отклонения от плана:
Новые вопросы:
Решения: (ссылки на D-xxx, если этап породил решение)
```

## E01 — Скелет, БД, миграции, конвейер проверки

Дата: 2026-10-11
Гейт: GREEN

Сделано:
- Gradle (Kotlin DSL), Java 21, Spring Boot 3.5, package-by-feature: `game`, `journal`,
  `message`, `user`.
- `docker-compose.yml` с Postgres 16 и профилями `dev`/`prod`; `MailConfiguration` профиля
  `prod` роняет старт без `spring.mail.host` и `chattergame.mail.from` (`D-079`).
- Liquibase: `db.changelog-master.yaml` и `changes/001-baseline.yaml` — 31 changeset, все
  31 таблицы из `REQUIREMENTS`, `BIGINT seq` в журнале, `uuid` внешние ключи, индекс
  `ix_inbox_entry_subject_chat_seq` сразу (`D-083`, `D-086`).
- Служебный source set `tools` и задачи `resetDb`, `liquibaseUpdate`, `printSchema`:
  миграции на гейте проверяются тем же кодом, что и в тестах.
- `scripts/gate.sh` с секциями «документация», «migrations», «build»,
  «unit_and_integration», «contract», «invariants»; пропущенный тест — красный гейт.
- Глобальные инварианты `PLAN §2` как исполняемые правила (`SourceScanner`, `SourceRules`)
  плюс канарейка, доказывающая, что детектор не выродился.
- Testcontainers-фикстура с порядком поиска базы `CHATTERGAME_DB_*` → локальная база →
  контейнер.
- OpenAPI и схема событий со снапшотами, сверяемыми на гейте.

Исправлено при приёмке, без выхода за объём этапа:
- `E01InvariantsTest` не компилировался: поле `@TempDir Path tempDir` использовалось, но
  не было объявлено, тестовый source set не собирался и гейт был красным.
- `MessageRepository.purge` содержал `DELETE FROM message`. Это была намеренная поломка для
  проверки красного пути, оставленная в дереве: она противоречила javadoc класса и держала
  инварианты `D-010` и `D-030` красными всегда. Метод удалён.

Критерии приёмки:
- `./scripts/gate.sh E01` — зелёный.
- Красный путь проверен на одноразовой копии дерева: добавленный `DELETE FROM message`
  в репозиторий-заглушку валит `noPhysicalDeletionOfDomainRows`, гейт краснеет.
  Рабочее дерево при этой проверке не правилось.
- Changelog применяется на чистой базе за один проход; повторный запуск Liquibase не
  применяет ни одного changeset; список таблиц совпал с `contract/expected-tables.txt`.

Отклонения от плана:
- Пакеты `chat`, `character`, `item`, `realtime`, `media`, `note`, `request`, `llm`,
  `participant` в `E01` не заведены: пустой Java-пакет не попадает в git и не несёт
  смысла. Они появятся на своих этапах (`E04`, `E05`, `E06`, `E07`, `E09`, `E12`, `E14`).
- Гейт прогнан на локальном Postgres 16 из PGDG, а не на контейнере `docker-compose`:
  в песочнице нет привилегий для старта dockerd. Порядок поиска базы в
  `PostgresTestSupport` это допускает, код проверок тот же.

Новые вопросы:
- Владельцу продукта: подтверждение этапа (п. 5 протокола гейта) пока не получено.
- Нужно ли зафиксировать в `AGENTS.md`, что пустые пакеты заранее не создаются, или

## E02 — Пользователь и локальная аутентификация

Дата: 2026-10-11
Гейт: GREEN

Сделано:
- Регистрация по логину и паролю (`D-091`): Argon2id (`spring-security-crypto`), пароль
  8–128 без требований к составу (`D-096`), логин в двух формах — отображаемой и
  NFC-нормализованной (`D-080`), почта необязательна и логином не является.
- Серверная сессия: HttpOnly cookie `CHATTERGAME_SESSION`, `SameSite=Lax`, 30 дней
  со скольжением, несколько устройств, «выйти» и «выйти на всех устройствах»; в БД только
  SHA-256 токена. Смена и сброс пароля гасят все сессии (`D-096`).
- `MailSender` + `LoggingMailSender` для `dev` с автоподтверждением адреса, `MailConfiguration`
  для `prod` роняет старт без `spring.mail.host` и `chattergame.mail.from` (`D-078`, `D-079`).
- Сброс пароля: одноразовый хеш-токен, TTL 60 минут, `RateLimiter` по адресу и по клиенту,
  одинаковый ответ на существующий и несуществующий адрес; выдача новой ссылки гасит прежнюю.
- `GET /me`, `PATCH /me`, `POST /me/password`, `POST /auth/logout-all`: профиль, отображаемое
  имя, почта, тема.
- `llm_credential`: несколько ключей на пользователя, один активный (частичный уникальный
  индекс из `001-baseline.yaml`), AES-GCM с ключом из секрета окружения, из API секрет
  не возвращается ни полем, ни маской (`D-093`).
- Удаление аккаунта (`D-095`): блокировка входа, анонимизация логина, почты и отображаемого
  имени, удаление сессий, токенов сброса и ключей LLM; персонажи и сообщения остаются,
  игры мастера архивируются событием `GAME_ARCHIVED` в журнале (`D-033`, `D-034`) и остаются
  читаемыми участникам.
- OpenAPI `0.1.0` заполнен путями аутентификации и профиля, снапшот обновлён синхронно.
- `Clock` вынесен в бин `ClockConfiguration`: TTL токена и скольжение сессии подменяются
  в тестах, а не проверяются сном.
- Тесты этапа с префиксом `E02`: `E02RegistrationTest`, `E02LoginNormalizationTest`,
  `E02SessionTest`, `E02PasswordResetTest`, `E02AccountDeletionTest`, `E02LlmCredentialTest`,
  `E02SecretsTest`, `E02LogSecretsTest` (всего 63 теста).

Критерии приёмки:
- `./scripts/gate.sh E02` — зелёный: 63 теста, пропущенных нет, контракт и список таблиц
  совпадают со снапшотами.
- Красный путь проверен на одноразовой копии дерева (`/tmp`, рабочее дерево не правилось):
  запись пароля в лог валит `noLogStatementTouchesPasswordsOrSecrets` и
  `passwordNeverAppearsInLogs`, `DELETE FROM message` в репозитории валит
  `noPhysicalDeletionOfDomainRows`; в обоих случаях гейт краснеет.
- Табличные проверки нормализации: `Вася` / `вася` / `ВАСЯ` и NFC против NFD дают один аккаунт;
  повторная регистрация — 409 с побайтово одинаковым ответом.
- Токен сброса одноразовый, не переживает смену пароля, истекает по TTL; ключ LLM лежит
  в БД шифртекстом (проверено выборкой из колонок), в ответе API поля секрета нет;
  смена пароля обрывает все сессии; удаление аккаунта не удаляет ни одного сообщения
  и оставляет игру мастера читаемой.

Отклонения от плана:
- Новая Liquibase-запись не добавлялась: таблицы `app_user`, `auth_identity`, `session`,
  `password_reset_token`, `llm_credential` и частичный уникальный индекс активного ключа
  уже есть в применённом `001-baseline.yaml` (`E01`). Отпечаток файла в манифесте не менялся,
  правка применённого changeset не потребовалась.
- Пути API — без префикса `/api` (`/auth/...`, `/me`, `/me/llm-credentials`): `PLAN` называет
  эндпоинт как `GET /me`, а прежний контур OpenAPI имел пустой `paths`, то есть выбор ничем
  не был закреплён. Если у владельца продукта есть ожидание префикса, смена затрагивает
  и снапшот, и `paths`.
- `scripts/gate.sh` расширен ветвью `stage_checks` по этапу: проверка «на E01 нет веб-слоя»
  перестала быть общим тестом, потому что `E02` этот веб-слой вводит. Правило не удалено из
  гейта, а перенесено в ветвь `E01`, и тест `e01WebLayerRuleStillEnforcedByGate` следит,
  чтобы оно не исчезло молча. Следствие: `./scripts/gate.sh E01` на дереве, где уже живёт
  `E02`, краснеет по конструкции — правило этапа проверяется в момент сдачи этапа, а не
  задним числом. Поведение на текущем дереве: `E02` зелёный, `E01` красный только по этой
  строке.
- `chattergame.mail.auto-verify-email` включён только в профиле `dev`; в `prod` ожидается
  реальное подтверждение по почте (`O01`).
- Пакеты `chat`, `character`, `item`, `participant`, `note`, `request`, `media`, `realtime`
  по-прежнему не заведены: появятся на своих этапах.
- Гейт прогнан на локальном Postgres 16 (PGDG), а не на контейнере: в песочнице нет
  привилегий для старта dockerd. Порядок поиска базы в `PostgresTestSupport` это допускает.

Новые вопросы:
- Владельцу продукта: подтверждение этапа (`PLAN §1`, п. 5) не получено, как и для `E01`.
- Нужен ли префикс `/api` у HTTP-путей, или `/me` и `/auth/...` в корне — это и есть контракт.
- Подтверждать ли адрес в `dev` автоматически при регистрации (сейчас `emailVerified=true`)
  или оставлять неподтверждённым до реального перехода по ссылке.
- Архивирование игр удалённого мастера на `E02` выполняет `GameArchiveService` (выдача `seq`
  под `SELECT … FOR UPDATE`, событие `GAME_ARCHIVED`). На `E03` его следует свести к вызову
  `GameMutationService`; подтвердить, что промежуточная реализация допустима.
- Как быть с проверками этапа в `scripts/gate.sh`, которые зависят от состояния дерева:
  `E01` запрещает веб-слой, `E02` его вводит, поэтому повторный прогон `E01` на позднем дереве
  краснеет. Сейчас это считается нормой: гейт — инструмент сдачи этапа, а не переоценки
  прошлых. Альтернатива — привязать проверки к коммиту этапа; решение за владельцем.

Решения: этап новых решений не породил.
