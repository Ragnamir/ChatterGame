# AGENTS.md

Платформа для проведения словесных (нарративных) игр. Мастер ведёт игру через чаты-локации,
игроки занимают персонажей. Масштаб: 4–10 игроков, 10–50 локаций, месяц асинхронной игры.

## Источник истины

| Документ | Назначение |
|---|---|
| `docs/REQUIREMENTS.md` | Замороженные требования: сущности, правила, состояния, матрицы прав |
| `docs/DECISIONS.md` | Журнал решений `D-001…`. Обоснование и следствия. Не переоткрывать |
| `docs/PLAN.md` | Этапы `E01…E14`, `F01…F05`, `O01…O03`, критерии приёмки, протокол гейта |
| `docs/STATUS.md` | Хронология прохождения этапов и возникшие вопросы |

Противоречие между `REQUIREMENTS` и `DECISIONS` — остановиться и спросить, а не выбрать молча.
Отсутствие случая в документах — спросить, а не додумать.

## Протокол работы

1. Один этап за раз. Следующий начинается только после зелёного
   `./scripts/gate.sh <STAGE>` и подтверждения владельцем продукта (`PLAN §1`).
2. Этап сдан, когда зелёные автоматические проверки, а не когда «код написан».
3. Каждый этап добавляет тесты с префиксом имени этапа, чтобы провал был адресным: `E08_*`.
4. Запись в `docs/STATUS.md` обязательна: что сделано, что отклонено от плана, какие
   вопросы появились.
5. Перед коммитом — `./scripts/check-docs.sh`. Незакоммиченные правки запрещено откатывать
   через `git checkout`/`git restore` по файлу: так уже были потеряны записи `D-086` и
   `D-087`. Для отката используйте точечную правку или `git stash`.

## Архитектурные запреты

Эти правила проверяются автоматически на каждом гейте (`PLAN §2`), а не на словах.

1. Миграции БД — только новая Liquibase-запись `db/changelog/changes/<NNN>-<stage>.yaml`.
   Применённые файлы не редактируются никогда.
2. Любая мутация игрового мира — только через `GameMutationService`, которая пишет событие
   в `game_event` и применяет эффект. Прямого `UPDATE` доменных таблиц из контроллеров нет.
   Причина: журнал — единственный источник истины для рассылки, аудита, resume и экспорта.
3. Видимость сообщений вычисляется при записи и материализуется в `inbox_entry` с
   субъектом-персонажем или субъектом-участием (`D-086`). Фильтрация «на чтении» запрещена:
   она размывает правило по всем запросам и даёт утечки при первом же изменении условий.
   Исключение — асинхронный backfill при создании участия-наблюдателя и при правке заметки
   (`D-087`): это запись, а не чтение.
4. Физическое удаление сущностей игры запрещено после `READY`, а в целом — никогда.
   Только `archived` с причиной.
5. Блокирующие внешние вызовы (LLM, SMTP, HTTP) внутри транзакции БД запрещены. Запрос к
   модели идёт 10–60 секунд и выбирает пул Hikari до нуля, после чего встаёт всё приложение.
6. Права проверяются на каждое входящее событие через `assertCanPost`, а не один раз при
   установке соединения. Сокет живёт часами; за это время персонажа снимают, мьютят,
   игру завершают.
7. Совпадение ключевых слов заметок не вычисляется в read-пути — только при записи
   сообщения, с асинхронным backfill при создании или правке заметки (`D-087`).
8. Секреты не хранятся в открытом виде: ключи LLM шифруются AES-GCM, в API возвращаются
   маской, в логи не пишутся (`D-093`).

## Стек

Java 21, Spring Boot 3.x, Gradle Kotlin DSL, package-by-feature монолит.
PostgreSQL 16, Liquibase YAML. Продакшн — один контейнер, ведущий несколько игр (`D-072`).
Аутентификация: серверная сессия + HttpOnly cookie, не JWT. Пароли: Argon2id.
Реалтайм: Spring WebSocket без STOMP, собственные JSON-события, handshake по cookie.
Идентификаторы: UUIDv7 как внешние PK; `BIGINT seq` — только порядок в журнале.
Тесты: JUnit 5, Testcontainers (реальный Postgres, не H2), AssertJ.
Frontend: React 18 + TypeScript + Vite + `vite-plugin-pwa` (`D-090`).
Секреты: ключ шифрования LLM-креденшалов и SMTP-пароль только из окружения, никогда из БД
или репозитория (`D-079`, `D-093`).

## Команды

```bash
./gradlew build              # компиляция и все тесты
./scripts/gate.sh E08        # проверки конкретного этапа
./scripts/check-docs.sh      # согласованность документации: ссылки D-xxx, карта этапов
docker compose up -d db      # локальный Postgres
./gradlew bootRun            # профиль dev по умолчанию
```

## Конвенции кода

- Комментарии только там, где код не выражает инвариант: порядок блокировок, обход,
  трейд-офф. Не пересказывать дифф и не описывать локальное поведение.
- В доменных объектах пустой список вместо `null`.
- Русские строки UI — только через ключи интернализации, с первого этапа.
- Логи структурированные, с `game_id` и `event_seq`, без текста сообщений и без
  закрытых историй.
- Импорт вверху файла, кроме случаев циклической зависимости или отложенной загрузки.

## Чего не делать без явного запроса

- Не добавлять зависимости «на будущее».
- Не вводить абстракции для одной реализации, кроме названных в `REQUIREMENTS`:
  `Fanout`, `MailSender`, `LlmProvider`, `AssetStore`.
- Не писать пуш-уведомления: отложены, нужны только таблицы-заготовки и карта событий.
- Не передавать мастерство и не вводить помощника мастера: решения `D-021`, `D-062`.
- Не вводить игровые механики (характеристики, броски, здоровье): решение `D-011`.
- Не вводить таймаут хода и любые вычисления по времени в пошаговом режиме (`D-060`).
- Не давать мастеру правку мира после `FINISHED` (`D-094`) и не делать галереи картинок
  (`D-098`).
- Не пушить в удалённую ветку и не открывать PR без явной просьбы.
